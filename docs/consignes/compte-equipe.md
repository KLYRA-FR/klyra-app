# Compte d’équipe et Bibliothèque

- **Compte d'équipe (Convex)** : seules les données partagées (comptes, équipe, puis rappels et calendrier) vont dans `convex/`, d'après `docs/CONVEX-PLAN.md`. Toute fonction publique commence par `exigerMembre` ou `exigerAdmin` (`convex/model/acces.ts`) et retrouve la personne par sa session, jamais par un argument. Seule exception, avant toute session : `connexion:demanderLien`, qui répond de la même façon pour toute adresse et applique le délai entre deux liens (`convex/model/limites.ts`, horloge du serveur) ; l'app ne demande jamais un lien par `auth:signIn` directement. L'interface passe par `src/lib/compte.tsx` (`useCompte`, `useEquipe`) ; les jetons de session sont chiffrés par `electron/compte.ts`. Convex Auth fait tourner le jeton de rafraîchissement (le serveur n'accepte que le dernier ou celui d'avant) : une écriture ratée est réessayée et ne bloque jamais les suivantes, une entrée illisible est gardée sans effacer les autres. NEVER de chaîne d'écritures qui reste rejetée (test : `pnpm test:jetons-compte`, et `pnpm test:session-maj` pour la session à travers une mise à jour). **Qui est l'utilisateur** : ALWAYS `useWorkspace().moi` (règles de `src/lib/identite.ts` : connecté, nom, rôle et couleur du compte ; sinon le profil de l'ordinateur ; photo et réglages toujours locaux), NEVER `state.currentUser` pour afficher ou nommer quelqu'un ; modifier son nom ou son rôle : `useMonIdentite().enregistrer`. Nouveau code d'erreur → le traduire dans `MESSAGES`. `membreActuel` vérifie aussi que la session existe encore (le jeton de Convex Auth vaut une heure) : NEVER lire l'identité par `getAuthUserId` ailleurs. Sessions des téléphones et déconnexion à distance : `convex/telephones.ts` (Réglages › Mobile). Tests : `pnpm test:convex` (backend en mémoire). Déploiement de dev : `pnpm dev:convex` ; la production n'est déployée que par l'action App.
- **Bibliothèque KLYRA** (`convex/bibliotheque.ts`, `src/lib/bibliotheque.tsx`) : définitions publiées volontairement, membres actifs seulement, auteur seul pour mettre à jour (version attendue) ou retirer. Ce qui part : `preparerPublication` (`convex/model/definitions.ts`, aussi utilisé par le serveur) : en-tête réduit (`CLES_PARTAGEES`), chemins personnels remplacés par `{{chemin:cle}}`, secret = refus. Jamais de cache sur le disque ; chaque lecture dit pour quel membre elle a été faite (`pour`). Une définition ajoutée est gardée à la version choisie (`definitions-recues/`) ; une mise à jour est **proposée**, jamais appliquée seule (`appliquer` refuse une fiche modifiée sauf `forcer`) ; modifier sa consigne dans l’app en fait une copie privée. Ce qu’un agent montre de son lien : `lienDe` (`src/lib/lien-bibliotheque.ts`), seulement pour la session qui l’a ajouté.
